# MediaHub 决策记录

本页记录影响产品范围、技术路线或阶段验收的决定。记录日期、状态、理由和关联方案。若后续用新结论替代，新增对应记录并链接原条目，让实施过程可以追溯。

## 已确定的产品方向

| 日期 | 决定 | 理由与影响 |
| --- | --- | --- |
| 2026-11-24 | 先供自己和家人使用 | 首版以家庭使用体验为目标。短期试用和长期部署按家庭的实际环境安排。[项目计划](plan.md) |
| 2026-11-24 | 手机与 PC 都提供完整的网页找片和播放 | 两类浏览器都作为 v0.1 的验收设备，页面与片库共用。[网页播放方案](web-mvp.md) |
| 2026-11-24 | 电视用于接收手机投屏，网页验收完成后再实现 | 投屏是最终交付项。以 v0.2 的实际手机和电视组合验收。[手机投屏方案](casting.md) |
| 2026-11-24 | 片源由项目侧搜集，每个阶段方案落文档 | 首批片源和新来源按出处、授权及可播放性管理。计划、方案和决策记录随仓库维护。[片源方案](media-sources.md) · [项目计划](plan.md) |

## 本计划采用的实施默认值

| 日期 | 默认做法 | 选择理由 |
| --- | --- | --- |
| 2026-11-24 | v0.1 在同一家庭局域网内从开发电脑试用 | 直接验证手机和 PC 能打开同一个站点，之后按实际使用选择长期运行设备。[网页播放方案](web-mvp.md) |
| 2026-11-24 | Vite、React、TypeScript 和本地 JSON 片库 | 三个样本只需要静态清单。电影与剧集可沿用同一数据结构和播放器。[网页播放方案](web-mvp.md) |
| 2026-11-24 | 以同源 MP4 和浏览器原生视频能力起步 | 片源可由家庭站点直接提供。第一批样本覆盖单部影片、原始集号和下一集。[片源方案](media-sources.md) |
| 2026-11-24 | GitHub Milestone 管版本，Issue 管验收，Markdown 保留方案 | 仓库同时承载交付进度、实现依据与测试结果。[项目计划](plan.md) |
| 2026-11-26 | 同一浏览器提供一条继续观看记录 | 家庭成员能快速接续上次观看，正常打开影片或选集仍从头播放。[网页播放方案](web-mvp.md) |

## 待确认的决策

| 问题 | 何时决定 | 需要的依据 |
| --- | --- | --- |
| 家庭服务长期运行在哪台设备上 | v0.1 家庭试用后 | 家里可常开的设备、安装方式和文件存储位置。 |
| 家人在家外是否也要使用 | 家庭使用范围明确时 | 访问需求与家庭网络条件。 |
| 首个投屏协议及网页和媒体的访问方式 | v0.2 设备验证任务 | 实际手机、浏览器、电视或盒子，及电视取流和远程控制的真机结果。[手机投屏方案](casting.md) |
| 首批样本之外接什么来源，是否接元数据服务 | 片库扩充时 | 可用授权、地区条件、媒体地址稳定性及人工维护量。[片源方案](media-sources.md) |
