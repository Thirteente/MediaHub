# MediaHub 项目计划

## 目标和使用场景

家人打开同一个 MediaHub 地址，在手机或 PC 上按片名找电影或电视剧，进入详情页后观看电影或指定剧集。网页播放验收后，手机可以把正在看的内容切到电视，并继续控制播放。

首个交付环境按同一家庭局域网设计，使用现有开发电脑试用。长期运行设备和是否需要从家外访问，在家庭试用后决定。片源由项目侧搜集和整理，第一版用有明确开放授权的作品验证完整体验。

## 里程碑

| 里程碑 | 交付 | 完成边界 |
| --- | --- | --- |
| [`v0.1` 网页播放](https://github.com/Thirteente/MediaHub/milestone/1) | 响应式片库、片名搜索、详情与选集、网页播放器、家庭网络启动说明 | 一部电影和两集系列作品从真实媒体文件播放。至少一台手机和一台 PC 在同一家庭局域网走完搜索、开播、控制和换集。 |
| [`v0.2` 手机投屏](https://github.com/Thirteente/MediaHub/milestone/2) | 一种经实机选定的投屏方式、手机控制、连接和退出反馈 | 至少一组实际手机和电视或盒子走完从当前进度投到电视、暂停、继续、跳转、换集和停止的流程。 |

扩充电影和剧集按片源单独安排。每一批先确认出处和可播放性，再进入片库。元数据接入、长期开机设备或家庭外访问有明确需求时，分别作为后续 Issue 推进。

## v0.1 网页播放

以下任务可以直接用作 GitHub Issue 标题和验收清单。按表中依赖推进，找片页面与播放器在数据契约确定后可以并行。

| 任务 | 依赖 | 验收条件 |
| --- | --- | --- |
| [建立家庭试播片库](https://github.com/Thirteente/MediaHub/issues/1) | [片源方案](media-sources.md) | 初始化可提供静态媒体的 Vite 工程和 Git 忽略规则。核对来源与署名，下载三个样本并按约定入库。通过同源媒体地址在手机和 PC 上直接开播、拖动，并检查范围请求。 |
| [实现片库搜索、详情与选集](https://github.com/Thirteente/MediaHub/issues/2) | 试播片库的数据结构 | 搜索已录入的片名和别名，空查询可浏览片库，找不到时有明确状态。电影提供播放入口，系列按原始集号展示并能进入指定集。手机窄屏和 PC 都能操作。 |
| [接通网页播放器](https://github.com/Thirteente/MediaHub/issues/3) | 试播媒体、详情与选集的路由契约 | 电影和剧集共用播放器。通过浏览器控件开始、暂停、拖动进度和全屏，有下一集时可切换。媒体失败或播放条目无效时可回到片库或详情，页面能正常操作。 |
| [完成家庭局域网验收](https://github.com/Thirteente/MediaHub/issues/4) | 网页与播放器可用 | 生产构建通过，用家庭手机与 PC 访问同一站点并执行[网页验收步骤](web-mvp.md#开发与验收顺序)。记录设备、浏览器、实际结果和待验证项，将真实安装和启动命令写入 README。 |

实施基线是 Vite、React 和 TypeScript。影片与剧集从版本控制内的小型 JSON 清单读取，MP4 与网页同源提供。开发阶段约定本地 `public/media/` 映射到站点的 `/media/`，媒体文件在开始实现时纳入 Git 忽略规则。网页播放器持有当前内容 ID、媒体地址、播放位置和播放状态，供下一里程碑复用。数据和页面契约见[网页播放方案](web-mvp.md)。

## v0.2 手机投屏

网页播放验收后，按[手机投屏方案](casting.md)登记目标设备和测试视频，先用同一份媒体文件验证电视能取流，再接入正式页面。

| 任务 | 依赖 | 验收条件 |
| --- | --- | --- |
| [确认目标设备和投屏方案](https://github.com/Thirteente/MediaHub/issues/6) | v0.1 验收 | 记录实际手机、浏览器、电视或盒子型号。依据真机验证确定协议、网页访问方式和媒体地址。验证当前播放位置、跳转和换集能通过目标路线实现。 |
| [接入手机投屏和播放控制](https://github.com/Thirteente/MediaHub/issues/7) | 目标设备验证通过 | 从手机播放器发起投屏，并在电视接续当前影片与进度。投屏期间手机控制暂停、继续、跳转、下一集和停止，连接状态与失败有反馈。 |
| [完成手机和电视真机验收](https://github.com/Thirteente/MediaHub/issues/8) | 投屏能力接通 | 用首批媒体做一轮连续测试，并覆盖设备不可达或播放失败的恢复路径。在方案记录设备、协议、状态和实测结果。 |

## 文档和 GitHub 管理

- [README](../README.md) 是唯一的文档入口，保留项目目标、启动方式和方案索引。[项目计划](plan.md) 管阶段顺序和完成条件，具体设计和验收记录归入对应阶段文档。
- GitHub 为两个版本各设一个 Milestone。每张 Issue 写一句目标、两到四条可核验的完成条件，必要时链接前置 Issue 和对应方案。Issue 创建后在任务或验收记录中补链接，进度统一在 GitHub 查看。
- 开发中产生的中间方案先写进所属文档，注明适用范围、选择理由、状态和验证方式。会影响其他任务的决定写入[决策记录](decisions.md)，并更新受影响的任务或文档。需要单独展开的新方案放在 `docs/`，登记到 README。
- 方案通过以实际验收结果为准。完成 Issue 时写下测过的设备或命令、结果和仍待验证的事项。里程碑以对应目标设备上的端到端验收为完成条件。
